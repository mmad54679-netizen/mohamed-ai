# Mohamed AI Android — 1.8.1

هذه نسخة Android تجريبية لمساعد عربي عام، مع وضع QUREO اختياري وآمن، وفريق افتراضي لصناعة التطبيقات. تختار JavaScript أو Python، ثم تسجل دخولك إلى QUREO. التشغيل الآلي محدود بعناصر وأنواع وأسئلة مدعومة؛ لا يضمن العمل على كل درس.

## ما الجديد في 1.8.1

- تقوية تعليمات الدقة في المساعد العام وQUREO وOpenManus والفريق الافتراضي والمعالجة المحلية: عدم اختلاق الأرقام أو المصادر أو النتائج، والتصريح بالافتراضات وما لا يُعرف.
- تفعيل مراجعة آلية ثانية للإجابات السحابية افتراضيًا، مع خيار للمستخدم لإيقافها. عند فشل المراجعة يُعرض تنبيه صريح بدل الادعاء بأنها تمت.
- تمرير الصورة والمراجع المتاحة إلى المراجعة عند توافرها، وإظهار ما إذا كانت المراجعة قد اكتملت؛ لا تُجرى على الوضع المحلي أو فريق التطبيقات.
- هذه المراجعة ليست تحققًا مستقلًا من الحقيقة؛ قد يخطئ النموذجان أو يفوتهما الخطأ، لذلك لا يمكن ضمان منع الهلوسة بالكامل. تحقّق من المعلومات المهمة والحديثة من مصادر مستقلة.

## ما يستطيع الحل الآلي فعله

في فحص الحساب الحقيقي، ظهر خيار «تسجيل الدخول للتعلّم» قبل حقول الدخول؛ الكود يتعامل الآن مع هذا الخيار المحدد مرة واحدة، لكن التطبيق لم يُختبر على جهاز Android. أظهر الحساب مسارَي **JavaScript** وPython، وتم تصحيح الواجهة لهذا الاختيار. في درس JavaScript الفعلي ظهر محرر مخصص وزر «تشغيل الكود»؛ هذا الزر والتنقل الموثوق بين لوحة المسارات والفصول غير مدعومين حاليًا. لذلك لم تُرسل إجابة ولم يُختبر الحل الآلي على ذلك الدرس.

يقتصر التنفيذ الحالي على عناصر DOM واضحة في صفحة QUREO:

- اختيار واحد من مجموعة راديو واضحة أو قائمة منسدلة، فيها من خيارين إلى ستة خيارات.
- تعبئة حقل نص أو رقم واحد.
- تعبئة محرر كود واحد.

الأنواع العامة المقصودة هي اختيار واضح، أو حقل نص/رقم، أو محرر كود واحد مع زر تشغيل معروف ومسموح. لكن محرر JavaScript وزر «تشغيل الكود» في الدرس الذي فُحص لا يطابقان حاليًا الزر المعروف، فيتوقف التطبيق دون تعبئة أو إرسال. يحتاج اقتراح النموذج إلى ثقة لا تقل عن 0.95 وإعادة فحص متسقة، لكن ذلك **ليس إثباتًا للصحة**. لا يواصل التطبيق إلا بعد ظهور تأكيد نجاح حديث وواضح من QUREO، ويتوقف عند السؤال الملتبس أو الشاشة غير المدعومة أو غياب نتيجة واضحة. لا يعيد إرسال إجابة تلقائيًا. الحلول المحفوظة تُستخدم فقط عند تطابق بصمة السؤال والمسار تمامًا، وتظل Java وJavaScript مسارين منفصلين.

هذا ليس فهمًا بصريًا عامًا لكل صفحة أو اختبارًا على كل أنواع دروس QUREO؛ يعتمد على ما تكشفه الصفحة كعناصر DOM، وقد تختلف صفحات QUREO الفعلية أو لا تعرض إشارات النجاح والأزرار التي يتعرف عليها التطبيق. لذلك لا يضمن إكمال درس أو مقرر كامل.

## الخصوصية وإعداد الاتصال

بيانات QUREO تُستخدم في نموذج تسجيل الدخول إلى QUREO فقط، ولا تُرسل لمزوّد النموذج. عند تشغيل المساعدة السحابية بعد التحقق من خادم HTTPS، قد تُرسل لقطة محدودة ومنقحة من السؤال وأزراره وخياراته وحقوله، وكذلك سياق المحادثة المحدود. التنقية ليست ضمانًا لإزالة كل معلومة شخصية؛ لا تكتب بيانات شخصية في المحادثة ولا ترفق صورًا فيها بيانات حساب.

كلمة مرور خادم المساعد منفصلة عن كلمة مرور QUREO. تُستخدم مؤقتًا للفحص والطلبات ولا تُحفظ في التخزين المحلي. إن لم تتوفر، يستطيع التطبيق تسجيل الدخول إلى QUREO، لكن قد يقتصر الحل على إجابة محفوظة محليًا تطابق السؤال والمسار حرفيًا.

تظل خدمة Worker الحالية غير متحققة في هذا الإصدار: المصدر المحلي `worker.mjs` محدّث لتوجيه الإجابات بالعربية وقصر المساعدة على QUREO، لكن لم يُنشر ولم يُختبر توافق الخادم الحي. إذا لم يتوافق الخادم الحي مع صيغة خطة الإجابة الحالية ذات `cross_check`، سيرفضه التطبيق ويتوقف قبل إرسال الإجابة. لم تُغير إعدادات الاستضافة أو الأسرار، ولم تُضف خدمة مدفوعة أو ترقية تلقائية؛ Groq لا يعمل إلا إذا فعّله مشغل الخدمة صراحةً.

## الاختبارات والحدود

اختبارات الكود تستخدم بيانات اصطناعية. فُتح حساب QUREO الحقيقي في متصفح سطح المكتب وفُحص درس JavaScript، لكن لم تُرسل إجابة ولم يتغير تقدم المقرر. لا تثبت الاختبارات أن تسجيل الدخول داخل التطبيق أو DOM الخاص بكل درس أو رسائل التصحيح أو الخادم الحي سيعمل. يلزم اختبار على جهاز Android حقيقي للتحقق من تدفق QUREO وشريط التحكم.

```sh
npm test
npm run test:worker
cd android-app
ANDROID_HOME=/home/ubuntu/Android/Sdk ./gradlew testDebugUnitTest assembleDebug
```

هذه نسخة Debug لحزمة `com.cue.qureohelper`، الإصدار `1.8.1` (versionCode 13)، بحد أدنى Android API 24 وtarget API 35، وليست نسخة متجر. لم يُبنَ APK لهذا الإصدار لأن Android SDK غير متاح في بيئة البناء الحالية.

## التكاملات

طبقة التكاملات موثقة في `CONNECTORS.md`، وتعرض `/api/capabilities` حالة GitHub وGoogle Drive وGmail وCalendar والبحث والصوت دون كشف الأسرار. التوفر لا يمنح الوكيل صلاحية الإرسال أو الحذف أو التعديل.

## تعدد المزوّدين (مجاني ومفتوح)

يجرّب الخادم المزوّدين بالترتيب وينتقل للتالي عند الفشل أو انتهاء الحصة. كلها اختيارية، ويكفي ضبط واحد منها:

| المزوّد | المتغيرات |
| --- | --- |
| Ollama (نموذج مفتوح يعمل عندك) | `OLLAMA_MODEL` مثل `qwen3:8b`، و`OLLAMA_BASE_URL` (الافتراضي `http://127.0.0.1:11434/v1`) |
| Gemini | `GEMINI_API_KEY` و`GEMINI_MODEL` (اختياري) |
| Groq | `GROQ_API_KEY` و`ENABLE_GROQ_FALLBACK=1` و`GROQ_MODEL` (اختياري) |
| OpenRouter | `OPENROUTER_API_KEY` و`OPENROUTER_MODEL` (الافتراضي `openrouter/free`؛ تحقق من اسم النموذج الحالي) |
| Cerebras | `CEREBRAS_API_KEY` و`CEREBRAS_MODEL` |
| أي خادم بصيغة OpenAI | `CUSTOM_PROVIDERS='[{"name":"mine","baseUrl":"https://.../v1","model":"...","apiKeyEnv":"MINE_KEY","vision":false}]'` |

- الترتيب: `PROVIDER_ORDER=ollama,gemini,groq,openrouter,cerebras` (الافتراضي). ما لم يُذكر يأتي بعده.
- الصور تُرسل فقط للمزوّدين الذين يدعمونها (Gemini، أو مزوّد مضبوط بـ `<NAME>_VISION=1` أو `"vision": true`).
- روابط `http` مسموحة للجهاز المحلي فقط؛ غير ذلك يجب `https`.
- الحصص والنماذج المجانية تتغير كثيرًا، فتحقق منها عند مزوّدك قبل الاعتماد عليها.

### تعديل نموذج مفتوح (Fine-tuning)

1. فعّل `LEARN_FROM_FEEDBACK=1` واجمع تقييمات «مفيد» من مستخدمين تثق بهم.
2. صدّرها: `node scripts/export-finetune.js` (ينتج `data/finetune.jsonl`).
3. راجع الأمثلة يدويًا، ثم درّب نموذجًا مفتوحًا بأسلوب LoRA (مثل Unsloth أو Axolotl)، وشغّله عبر Ollama، واضبط `OLLAMA_MODEL` على اسمه.
4. قارن قبل وبعد بـ `npm run eval`.

## Mohamed Code — وكيل برمجة في الطرفية (على طراز Claude Code)

أداة CLI تعمل على مشروعك مباشرة بنماذج مجانية أو محلية (نفس متغيرات المزوّدين أعلاه):

```
OLLAMA_MODEL=qwen3:8b node cli/mohamed-code.js          # جلسة تفاعلية
node cli/mohamed-code.js -p "أصلح الاختبار الفاشل"        # مهمة واحدة
node cli/mohamed-code.js --auto-edit --cwd ~/myproject
```

- **الأدوات:** `list_dir` و`read_file` و`grep` و`edit_file` و`write_file` و`run_command`. الوكيل يستكشف، يعدّل، ثم يشغّل الاختبارات ليتحقق.
- **الموافقات:** افتراضيًا يسأل قبل كل تعديل وكل أمر (`y/n/a`). `--auto-edit` يقبل التعديلات فقط، و`--yes` يقبل كل شيء (والأوامر الخطرة تبقى محظورة).
- **الأمان:** لا يخرج من مجلد المشروع (حتى عبر الروابط الرمزية)، ولا يقرأ أو يكتب `.env` والمفاتيح، ولا يمرّر الرموز السرية لعمليات الأوامر، و`git push` معطّل إلا بـ `--allow-push`.
- **ذاكرة المشروع:** ضع تعليماتك في `MOHAMED.md` بجذر المشروع وسيقرؤه تلقائيًا (مثل CLAUDE.md).
- **التبديل بين المزوّدين:** إن فشل نموذج أو انتهت حصته ينتقل للتالي تلقائيًا.
- **حدود:** النماذج المجانية الصغيرة أضعف في استدعاء الأدوات وتحتاج مراجعتك؛ راجع التعديلات (`git diff`) قبل الدمج. يتطلب نموذجًا يدعم Tool Calling.


## تفعيل OpenManus اختياريًا

شغّل الجسر الموجود في `openmanus-bridge/` من داخل تثبيت OpenManus الرسمي المعزول، ثم اضبط `OPENMANUS_URL` و`OPENMANUS_TOKEN` على خادم Node.js. التطبيق لا يتصل بخدمة Python مباشرة ولا يخزّن سر الجسر. اختيار OpenManus لا يعمل على Worker قديم؛ يلزم نشر نسخة Node.js الحالية. اتبع ملف README الخاص بالجسر، ولا تفتح منفذه للإنترنت.
